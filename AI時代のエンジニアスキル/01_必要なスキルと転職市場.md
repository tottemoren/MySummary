# 01. AI時代に必要なスキルと転職市場

[← 目次に戻る](README.md)

## 前提：変化の本質

AIでコードを書くコストは大きく下がった。そのぶん、次の3つの価値が上がっている。

- **何を作るべきか決める力**
- **AIの出力が正しいか判断する力**
- **作ったものに責任を持つ力**

「手を動かしてコードを書く人」から「AIを指揮して成果を出す人」へ、役割が移っている。

---

## 1. これから必要なスキル

### ① 基礎力（以前より重要）
- **コードを読んでレビューする力**：AIが書いたコードのバグ、セキュリティの穴、非効率な処理を見抜く
- **設計力**：アーキテクチャ、データモデリング、API設計。AIは部分の最適化は得意だが、全体の整合性をとるのは人間の役割
- **CS基礎**：ネットワーク、DB、並行処理、セキュリティ。知らないと、AIの「もっともらしい間違い」に気づけない
- **デバッグ力**：AIが解決できない問題を切り分けて、原因を突き止める力

### ② AI活用力（新しく必要になった力）
- **タスクの分解と指示出し**：曖昧な要求を、AIが実行できる具体的なタスクに分ける
- **コンテキスト設計**：CLAUDE.md、仕様書、テストなどを整備して、AIが正しく動ける環境をつくる
- **エージェント型の開発フロー**：Claude Code や Cursor のようなツールで、複数のタスクを任せ、レビューし、統合する
- **検証の仕組みづくり**：テスト、型、CI、Lint を整え、AIの出力を自動で検証できるようにする

### ③ AIを組み込んだプロダクト開発
- LLM API の活用（プロンプト設計、ツール呼び出し、RAG、エージェント設計）
- 評価（Eval）の設計：AI機能の品質をどう測るか
- コスト、レイテンシ、ハルシネーションへの対策

### ④ ビジネス・対人スキル
- **課題を定義する力**：「何を作るか」「なぜ作るか」を言語化する
- **ドメイン知識**：業界や業務への深い理解は、AIでは代わりにくい強み
- **コミュニケーション**：ステークホルダーとの合意形成、要件の調整

---

## 2. 転職市場で求められるエンジニア像

| タイプ | 特徴 | 評価される理由 |
|---|---|---|
| **プロダクトエンジニア** | 企画から実装、リリース、改善まで一人で回せる | AIで実装が速くなり、少人数で広い範囲を担当できる人が重宝される |
| **AI/LLM アプリケーションエンジニア** | LLM を組み込んだ機能・エージェントを設計、実装、評価できる | 需要が最も伸びている領域で、人材が不足している |
| **テックリード／アーキテクト** | 設計判断とレビューで品質を担保する | AIが大量に生むコードの品質を管理する役割が重要になっている |
| **プラットフォーム／DevEx エンジニア** | 開発組織全体のAI活用基盤を整える | 組織の生産性を何倍にもできる |
| **ドメイン特化型エンジニア** | 金融、医療、製造などの業務知識と技術を併せ持つ | AIで代わりにくく、希少性が高い |

逆に、**仕様どおりにコードを書くだけ**の役割は、市場価値が下がりつつある。

### 面接で見られやすいポイント
- 普段の開発でAIをどう使っているか（具体的なワークフローを説明できるか）
- AIの出力をどう検証しているか
- AIで生産性がどれだけ上がったか（数字で示せると強い）
- 技術的な判断の根拠を説明できるか

---

## 3. 今日からできるアクション

1. **AIエージェントを日常的に使い込む**：Claude Code などで実際のプロジェクトを進め、「任せ方」の勘所をつかむ
2. **LLM を使ったアプリを1つ作って公開する**：API 連携、ツール呼び出し、評価まで含めるとポートフォリオとして強い
3. **レビューする側に回る経験を積む**：自分で書くより、読んで判断する時間を増やす
4. **成果を言語化して残す**：「AIを活用して○○を△日で構築」「工数を□%削減」のように記録する（→ [07](07_知識と経験のまとめ方・保管方法.md)）
5. **得意なドメインを1つ持つ**：技術に加えて、業界知識を掛け合わせる

---

## まとめ

> AIに置き換えられるのは「書く作業」で、「判断」と「責任」は置き換えられない。
> 基礎をしっかり持ったうえでAIを使いこなし、課題の発見から価値提供までをやり切れるエンジニアが、これから最も求められる。
