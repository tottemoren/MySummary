## 全体を通した要点

1. **AIに置き換えられるのは「書く作業」**。何を作るか決める力、出力の正しさを判断する力、責任を持つ力の価値が上がっている。
2. **AIの性能を引き出せるかは、エンジニア自身の基礎力しだい**。的確に頼むための語彙と設計力、出力を見抜くためのレビュー力が必要。
3. **AIの仕組みを知ると、癖が分かる**。もっともらしい間違い（ハルシネーション）、古い知識、文脈の限界を前提に、検証の仕組みを作る。
4. **ドキュメントはリポジトリ内の Markdown で、コードと一緒に更新する**。CLAUDE.md・仕様（Spec）・ADR・用語集・テストが特に効く。
5. **AIは局所的に最適、全体では膨らみがち**。定期的に全体を把握し、削る判断は人間が行う。
6. **確認の基準は公式ドキュメントと実際の使用例**。ブログやAIの説明だけで判断しない。
7. **学んだことは記録して再利用する**。特にトラブルシューティングと、数字付きの実績ログ。
8. **ツールは「人間とAIの間違いを機械で止める」ために使う**。型・Lint・テスト・CI が要。
