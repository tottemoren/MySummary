# 10. 用語集

## API・HTTP

| 用語 | 意味 | ノート |
|---|---|---|
| API | 処理を外から使うための窓口と、その使い方の約束 | [01](01_APIとは何か.md) |
| エンドポイント | APIの1つの窓口。URL とメソッドの組み合わせ（例：`POST /api/articles`） | [01](01_APIとは何か.md) |
| HTTPメソッド | リクエストの種類。GET（取得）、POST（作成）、PUT（置き換え）、DELETE（削除）など | [06](06_設計の考え方.md) |
| ステータスコード | 結果を表す3桁の数字。2xx 成功、4xx 利用者側の問題、5xx サーバー側の問題 | [06](06_設計の考え方.md) |
| 冪等性（べきとうせい） | 何回送っても結果が同じ性質。GET・PUT・DELETE は冪等、POST は冪等でない | [06](06_設計の考え方.md) |
| ヘッダー | リクエスト・レスポンスに付く付帯情報（データの形式、認証情報、Cookie など） | [08](08_HTTPと認証の仕組み.md) |
| ボディ | リクエスト・レスポンスの本文（JSON など） | [08](08_HTTPと認証の仕組み.md) |
| JSON | データをやりとりするための文字の形式（`{"title": "..."}`） | [08](08_HTTPと認証の仕組み.md) |
| HTTPS | 通信を暗号化した HTTP。今の Web では必須 | [08](08_HTTPと認証の仕組み.md) |

## バックエンドの構成

| 用語 | 意味 | ノート |
|---|---|---|
| ルーティング | URL と、担当する処理の対応表 | [02](02_リクエストの流れとSpringBootの基本の仕組み.md) |
| ミドルウェア（Filter / Interceptor） | 全リクエストに共通の処理を、Controller の手前で行う仕組み | [02](02_リクエストの流れとSpringBootの基本の仕組み.md) |
| Controller（Handler） | リクエストを受け取り、処理を頼み、結果を返す係 | [02](02_リクエストの流れとSpringBootの基本の仕組み.md) |
| Service | ビジネスロジック（業務のルール）を書く層 | [03](03_言語・フレームワークごとのバックエンド構成.md) |
| Repository（Store） | DB への保存・取得を担当する係 | [03](03_言語・フレームワークごとのバックエンド構成.md) |
| Entity | DB のテーブルに対応するクラス | [03](03_言語・フレームワークごとのバックエンド構成.md) |
| DTO | データの受け渡し専用のクラス。受け取る・返す項目を限定する | [04](04_セキュリティの基本.md) |
| アノテーション | `@` で始まる、クラスやメソッドの役割をフレームワークに伝える目印（Java） | [02](02_リクエストの流れとSpringBootの基本の仕組み.md) |
| DI（依存性の注入） | 必要な部品を自分で作らず、外から渡してもらう仕組み | [02](02_リクエストの流れとSpringBootの基本の仕組み.md) |
| ORM | DB のテーブルとプログラムのオブジェクトを対応させる仕組み（JPA、ActiveRecord、Eloquent） | [03](03_言語・フレームワークごとのバックエンド構成.md) |
| Active Record | 1つの Model がデータと保存処理を兼ねる設計（Rails、Laravel） | [03](03_言語・フレームワークごとのバックエンド構成.md) |
| 規約より設定（Convention over Configuration） | 名前や場所の規約に従えば、設定を書かずに自動でつながる考え方（Rails） | [03](03_言語・フレームワークごとのバックエンド構成.md) |
| 静的型付け / 動的型付け | 型を実行前に決める（Java、Go）/ 実行時に決まる（Ruby、PHP） | [03](03_言語・フレームワークごとのバックエンド構成.md) |

## セキュリティ

| 用語 | 意味 | ノート |
|---|---|---|
| 認証 | 「あなたは誰？」を確かめること | [04](04_セキュリティの基本.md) |
| 認可 | 「あなたはそれをしてよい？」を確かめること | [04](04_セキュリティの基本.md) |
| IDOR | ID を書き換えるだけで他人のデータに触れてしまう、認可漏れの典型 | [04](04_セキュリティの基本.md) |
| ハッシュ化 | 元に戻せない形に変換すること。パスワードの保存に使う（BCrypt など） | [04](04_セキュリティの基本.md) |
| レート制限 | 一定時間内のリクエスト回数を制限すること。総当たり攻撃の対策 | [04](04_セキュリティの基本.md) |
| SQLインジェクション | 入力に SQL を混ぜて、DB への命令を書き換える攻撃 | [04](04_セキュリティの基本.md) |
| プレースホルダ | SQL の値の部分を `?` にして、入力を SQL として解釈させない書き方 | [03](03_言語・フレームワークごとのバックエンド構成.md) |
| マスアサインメント | 送られてきたデータをそのまま保存し、触らせたくない項目まで変えられてしまう問題 | [04](04_セキュリティの基本.md) |
| XSS | 入力に仕込まれたスクリプトが、他人のブラウザで実行される攻撃 | [09](09_フロントエンド側の観点.md) |
| CSRF | Cookie の自動送信を悪用し、利用者に意図しない操作をさせる攻撃 | [08](08_HTTPと認証の仕組み.md) |
| CORS | どの Web サイトからこの API を呼んでよいかを、ブラウザに伝える仕組み | [04](04_セキュリティの基本.md) |
| 許可リスト方式 | 「許可するもの」だけを列挙し、それ以外をすべて拒否する方式 | [04](04_セキュリティの基本.md) |
| 環境変数 / `.env` | 秘密情報や環境ごとの設定を、コードの外から渡す仕組み | [04](04_セキュリティの基本.md) |
| OWASP Top 10 | Web アプリの代表的なセキュリティリスクのランキング | [04](04_セキュリティの基本.md) |

## 認証の方式

| 用語 | 意味 | ノート |
|---|---|---|
| Cookie | サーバーの指示でブラウザが保存し、自動で送り返す小さなデータ | [08](08_HTTPと認証の仕組み.md) |
| セッション | ログイン状態をサーバー側に保存し、ID だけをクライアントに持たせる方式 | [08](08_HTTPと認証の仕組み.md) |
| JWT | 誰か・期限などの中身に署名したトークン。サーバーは署名を検証するだけでよい | [08](08_HTTPと認証の仕組み.md) |
| HttpOnly / Secure / SameSite | Cookie の属性。JS から読めない / HTTPS のみ / 他サイトからは送らない | [08](08_HTTPと認証の仕組み.md) |
