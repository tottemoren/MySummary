## 全体を通した要点

1. **API は処理ではなく「窓口と約束」**。実装は後から直せるが、公開した約束は変えにくい。
2. **どの言語でもリクエストの流れは同じ**（ルーティング → ミドルウェア → コントローラー → ロジック → データアクセス → DB）。違うのは、層の分け方と部品のつなぎ方。
3. **Rails・Laravel は Active Record**（Model が Entity と Repository を兼ねる）、**Go は全部を明示的に書く**。読む前に「どの流派か」を見極める。
4. **サーバーは送られてきたものを信用しない**。特に**認証（誰か）と認可（してよいか）は別物**で、認可の書き忘れが最も多い事故。
5. **リファクタリングは動作を変えずに構造を整えること**。テストを命綱に、小さく、機能追加と混ぜずに進める。
6. **AI時代もリーダブルコードは必要**。AI は名前で探し、周りのコードをまねる。名前・重複・一貫性・「なぜ」のコメント・テストの価値はむしろ上がった。
7. **設計は「途中で失敗したら」「サーバーが増えたら」「部品を替えたら」を考えること**。トランザクション、DB制約、ステートレス、抽象化はその答え。
8. **コードは1つの機能を入口から出口まで追い、同じ問いで比べて読む**。違いが「なぜそう書くのか」の気づきになる。
9. **HTTPは前のリクエストを覚えていない**。ログイン状態は、セッションや JWT という「証拠」を毎回送ることで実現する。
10. **フロントエンドのコードは利用者の手の中にある**。画面の制限は UX のため、データを守るのはサーバーの仕事。
